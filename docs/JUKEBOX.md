# Jukebox · 联机试玩版 02

音乐、插画与隐藏身份的线上桌游试验工具。中文界面，电脑 / 手机共用房间，2–8 个席位；语音由玩家自行通过微信或 Discord 接通。

## 第一次试玩

1. 房主打开网址，输入昵称，创建房间。
2. 复制房间码旁的邀请链接，发给朋友。也可让朋友在首页输入六位房间码。
3. 每个人点击「开启声音」，建议佩戴耳机。等音频就绪后房主开始第一轮，并点「依次播放」。
4. 房主按页面下方按钮推进流程；玩家在主区域查看整行大幅手牌，直接点击选牌并确认。手机可横滑看大图或切换双列对照。
5. 轮末直接在「玩家积分」中编辑每个人的总分，点击各行的保存按钮。房主管理中也有同样入口。玩法中列出当前身份模式的计分方案，系统不自动加分。

网页需保持前台。浏览器可能在切换语音或锁屏后暂停播放，回来后重新开启声音。同一手机同时使用语音和浏览器的混音、耳机路由需要实机测试。

## 两种模式

- **猜音乐（2–8 人）**：作者按座位轮换，选目标音乐和一张图。其他人看图猜 A/B/C。默认猜完再解释；可设置先解释再猜。
- **隐藏身份（3–8 人；建议 4–8）**：每轮随机一名作者、一名间谍，其余为普通玩家。作者秘密选曲与图，间谍获得目标再选图，普通玩家在不知道目标时选图。所有图片各归其主，公开目标后依次解释。默认作者找间谍、普通玩家找作者、间谍不投票。此为待试玩预设，不宣称已验证平衡。

可调整手牌 3–8 张、下一轮模式 / 曲组 / 解释时机。自由投票可配置题目、音乐或玩家选项、参与身份、自投与弃权。房主可以重新开放未公开的选牌、强制推进、结束揭晓、重开一轮、重新发牌、记分与移交房主。揭晓前的身份类投票只公布匿名计票，避免通过投票资格直接暴露身份。

## 30 段音乐与 65 张插画

- 65 张原有插画均已从完整打印 PDF 提取为 900×1200 JPEG，另有 300×400 缩略图。
- 原十组共 30 段片段的编排保留在 `lib/catalog.json`。
- 根据用户 2026-10-05 对朋友私下测试用途的明确要求，原 30 段音乐均直接托管播放，无需玩家手动导入。每个文件的 SHA-256 与原包逐一核对。原十组编排没有变化，旧房间的三个补充组保持兼容。
- 在线录音署名在网站「作品与录音说明」和 `public/audio/ATTRIBUTION.txt`；逐首审计见 `docs/asset-audit.json`。
- 卡图为 AI 辅助生成、参考皮耶罗风格的原创游戏插画，并非历史画家的原作。

## 数据与重连

房间状态存于 D1 SQLite，使用版本条件更新与操作编号去重，避免同时提交覆盖或重试造成重复加分。游戏操作通过 HTTP 更新，客户端每约 1.2 秒读取自己的视图；音乐按服务器时间安排三秒后的播放起点，并在本机纠正进度。不是逐采样精度同步。

玩家凭证存于浏览器；服务器只存凭证摘要。积分可直接设置为整数总分（包括 0 与负分），使用原分数校验避免同时修改覆盖。每次读取只返回自己的手牌、角色及有权知道的目标，不把整桌秘密发给房主或浏览器。刷新后恢复同一座位；跨浏览器不自动恢复身份。房主离线 90 秒可由其他玩家接管。72 小时无人操作后，房间在应用层失效；不是承诺数据库立即删除。

## 验证

- `node node_modules/typescript/bin/tsc --noEmit`
- `node tests/game.test.mjs`：16 个规则与信息隔离场景，覆盖 2–8 人、多轮回收牌组、角色差异、自由投票、去重与房主接管。
- `node tests/store.test.mjs`：SQLite 适配器下并发加入、并发提交、凭证隔离、重复加分去重与持久化恢复。适配器检验 SQL/CAS 行为，不代表生产网络延迟。
- `node tests/interface.test.mjs`：检查房主看到全部 8 个可编辑总分、普通玩家只读，大图手牌与当前计分文案。此为服务端组件渲染验证，非浏览器交互验证。
- 原生 Sites 构建与部署。

本环境没有 Sites 要求的 control-browser 能力，未运行浏览器端点击、视觉截图或真实声音测试。手机 Safari、微信内置浏览器、语音同时播放，以及中国大陆连接质量需实机确认。建议优先使用手机系统浏览器。

## 开发入口

- `app/page.tsx`：房间与大厅界面。
- `app/components/RoomScene.tsx`、`app/room.css`：大图手牌和完整桌面布局。
- `app/components/Scoreboard.tsx`：直接编辑总分。
- `app/components/SupportPanels.tsx`：玩家玩法、计分方案和曲库。
- `lib/game.ts`：纯游戏状态变更及私密视图；更改规则优先从这里入手。
- `lib/store.ts`：D1 持久化、凭证与并发控制。
- `app/api/`：建房、加入、读取和操作。
- `db/schema.ts` 与 `drizzle/`：数据库定义与迁移。
- `.openai/hosting.json`：同一个 Site 的配置。后续更新保留 project_id，使用原生 Sites 工作流。

使用 pnpm 管理依赖；无需额外登录服务、语音 SDK、外部字体或跨站音频资源。
